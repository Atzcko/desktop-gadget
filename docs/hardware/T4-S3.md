# LilyGO T4-S3 — hardware facts

Everything here is read out of the [[LilyGo AMOLED library]] source, not from marketing pages. Source of truth: `src/LilyGo_AMOLED.h`, `src/initSequence.h`, `boards/T-Display-AMOLED.json`.

## Identity

| Property | Value |
|---|---|
| MCU | ESP32-S3R8 |
| Board ID enum | `LILYGO_AMOLED_241` |
| Flash | 16 MB, QIO mode @ 80 MHz |
| PSRAM | 8 MB **OPI** (`memory_type: qio_opi`) |
| Partitions | `default_16MB.csv` |
| USB VID:PID | `0x303A:0x1001` (native USB-Serial-JTAG) |
| Port on this Mac | `/dev/cu.usbmodem2101` |

> [!important] Verified connected
> `ioreg` reports `Espressif "USB JTAG_serial debug unit"` at `0x303A:0x1001` — an exact match for the `hwids` entry in the board JSON. The board is plugged in and enumerating.

## Display — RM690B0 over QSPI

| Property | Value |
|---|---|
| Panel | 2.41" AMOLED, driver **RM690B0** |
| `RM690B0_WIDTH` | **600** |
| `RM690B0_HEIGHT` | **450** |
| Bus | QSPI, 36 MHz, 8-bit command / 24-bit address |
| Internal framebuffer | **none** (`framebuffer: false` in `BOARD_AMOLED_241`) |
| Full refresh required | no (`fullRefresh: false`) — partial flush is allowed |

### Pins (QSPI)

| Signal | GPIO |
|---|---|
| D0 | 14 |
| D1 | 10 |
| D2 | 16 |
| D3 | 12 |
| SCK | 15 |
| CS | 11 |
| RST | 13 |
| TE | 18 |

> [!tip] Landscape is free
> The library defines the panel as 600 wide × 450 tall, and `beginAMOLED_241()` ends with `setRotation(0)`. Rotation 0 for this board sets `_width = 600`, `_height = 450`. **The 600×450 landscape orientation the project wants is the default** — see [[D004 - Rotation 0 is already landscape]].

### Rotation table (`BOARD_AMOLED_241`)

| Rotation | Resolution | `_offset_x` | `_offset_y` | Touch transform |
|---|---|---|---|---|
| **0** (default) | **600×450** | 0 | 16 | swapXY, mirror(false,true) |
| 1 | 450×600 | 16 | 0 | none |
| 2 | 600×450 | 0 | 16 | swapXY, mirror(true,false) |
| 3 | 450×600 | 16 | 0 | mirror(true,true) |

The `_offset_y = 16` in landscape is a panel-internal window offset the driver applies inside `pushColors` — it is not something application code compensates for.

## Touch — CST226SE

- I²C at `CST226SE_SLAVE_ADDRESS`, driver class `TouchDrvCSTXXX` with model `TouchDrv_CST226`.
- Pins: SDA 6, SCL 7, IRQ 8, RST 17.
- Probed by `Wire.beginTransmission()` before init — if it does not ACK, the library logs and continues with touch offline rather than failing `begin()`.
- Coordinate limits and axis swap/mirror are re-applied on every `setRotation()`.

## Power

- PMU: **SY6970** on the same I²C bus (SDA 6, SCL 7, IRQ 5), `PMICEnPins = 9`.
- `beginAMOLED_241(disable_sd, disable_state_led)` calls `SY.enableMeasure()` and `SY.disableOTG()`.
- Project is USB-powered only — see [[D007 - Skip SD, keep charge LED default]].

## SD card

- Onboard slot on SPI: MISO 4, MOSI 2, SCK 3, CS 1.
- **Unused in this project.** Passing `disable_sd = true` skips `SPI.begin()` and `SD.begin()` entirely, which keeps those four GPIOs and the SPI peripheral free and shaves boot time.
