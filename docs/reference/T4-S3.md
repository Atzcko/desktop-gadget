# T4-S3 — the board

LilyGO T4-S3: ESP32-S3R8 (16 MB flash, 8 MB OPI PSRAM), 2.41" RM690B0 AMOLED
450×600 over QSPI at 36 MHz, CST226SE capacitive touch, SY6970 PMU, USB-C.
Sources of truth: the library board config (`BOARD_AMOLED_241` in
`LilyGo_AMOLED.h`) and the schematic
(`~/.local/src/LilyGo-AMOLED-Series/schematic/T4-S3-240719.pdf`). Everything
below was read from those two, not from README tables — see
[[LilyGo AMOLED library]] for why that distinction exists.

## Identity

| | |
|---|---|
| USB ID (upload port detection) | `303A:1001` — stable; the port *name* is not |
| mDNS | `flipclock.local` |
| Panel | RM690B0, 450×600, QSPI, 36 MHz, TE on GPIO18 |

## Pin map — who owns what

**Owned by the firmware / board** (never touch from an app — [[D035 - The Lab may only touch pins the firmware does not own]]):

| GPIO | Role |
|---|---|
| 10, 11, 12, 14, 15, 16 | display QSPI (D1, CS, D3, D0, SCK, D2) |
| 13 | display reset |
| 18 | display TE — **on the header, still owned** |
| 6, 7 | internal I²C: SY6970 PMU + CST226SE touch + P4 plug |
| 5 | PMU IRQ |
| 8 / 17 | touch IRQ / touch reset |
| 9 | PMIC enable — driving this can kill power |
| 0 | BOOT button — **readable** in the Lab, never an output ([[D036 - GPIO0 is readable, never drivable]]) |
| 19, 20 | USB D− / D+ |
| 26–37 | SPI flash + OPI PSRAM |
| 45, 46 | strapping |

**Free on the 2×15 header** (the Lab's whitelist):

| GPIO | Note |
|---|---|
| 21, 38, 39, 40, 41, 42, 47, 48 | fully free |
| 43, 44 | U0TXD / U0RXD — ROM boot chatter on 43, otherwise free; the UART tab default |
| 1, 2, 3, 4 | SD socket (CS, MOSI, SCK, MISO) — free while no card is inserted |

Also on the header: 3V3, GND, VBUS, BAT, and the internal I²C pair (6/7).
Two 4-pin 1.0 mm plugs: **P2** = UART0 (43/44 + power), **P4** = internal I²C
(6/7 + power) — a Qwiic-style port on the live PMU/touch bus.

> [!warning] On the header ≠ free
> GPIO18 reaches the header **and** is the display's tearing-effect line.
> It is the reason the Lab's whitelist is a written decision and not just an
> array.

## The LED on the back — no GPIO at all

`BOARD_AMOLED_241` declares `pixelsPins = -1`: this board has **no
firmware-addressable LED pin**. (The 1.47" sibling has a NeoPixel on GPIO18;
ours does not.)

**Confirmed on the schematic** (`T4-S3-240719.pdf`, page 1, the SY6970 block),
not just inferred from the library:

```
VSYS ──[ R47, 1K ]──▶|── LED1 (net LED_G) ──── U5 pin 4  STAT
```

The LED's anode sits on VSYS through a 1 K resistor; its cathode goes to the
**SY6970's STAT pin**, which the PMU sinks. No ESP32 pin is involved anywhere
in that path, so there is nothing to `pinMode()`. It is reached over the
internal I2C bus (6/7) — by API, never by pin:

```cpp
amoled.setChargingLedMode(XPOWERS_CHG_LED_OFF);        // off
amoled.setChargingLedMode(XPOWERS_CHG_LED_BLINK_1HZ);  // or 4HZ
amoled.setChargingLedMode(XPOWERS_CHG_LED_ON);         // solid
amoled.setChargingLedMode(XPOWERS_CHG_LED_CTRL_CHG);   // follow charging (default)
```

So it *is* usable as a status indicator — just not as a GPIO.
See [[D007 - Skip SD, keep charge LED default]] for why it is currently left
on the charger's control.

## The BOOT button (GPIO0) — now the orientation control

Since v1.22.0 a short press cycles the panel 90° per press
([[D043 - Orientation is the clock's job; apps borrow landscape]]), reading
the pin with `INPUT_PULLUP` (the internal pull-up — an earlier revision of
this note claimed an external one the schematic does not show).


A strapping pin sampled only at reset; afterwards an ordinary active-low
input. **Use `INPUT_PULLUP`** — the library's own examples do, and v1.22.0
learned why the hard way: with plain `INPUT` the pin floats and produces
phantom presses (an earlier revision of this note claimed an external 10 K
pull-up on the strength of nothing verifiable; the schematic shows none). Held **during** reset it still enters USB download
mode, which is a feature: the flash escape hatch survives firmware
repurposing the button. Any enclosure must leave it pressable at plug-in
time or the recovery path is lost.
